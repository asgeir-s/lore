# Installing and releasing Lore

- Use `npm run install-app` to build/install a local update. On macOS this reserves a fresh `CFBundleVersion` build number, signs the complete bundle, and verifies the signature before installation. Do not replace the executable alone or install a bundle that fails verification.
- For a release, increase the semantic version and keep `package.json`, both root versions in `package-lock.json`, `src-tauri/Cargo.toml`, Lore's entry in `src-tauri/Cargo.lock`, and `src-tauri/tauri.conf.json` synchronized. Local build numbers increase automatically; they do not require semantic-version changes on every install.
- Keep the bundle identifier `com.lore.notes` unchanged. Neither a version bump nor a build-number increment preserves macOS permissions on its own. Use a consistent Apple signing certificate through `APPLE_SIGNING_IDENTITY` for that. Ad-hoc builds may require permission again after rebuilding; do not promise otherwise or weaken signing requirements to avoid consent.
- Recording uses CPAL Core Audio taps for system audio. Keep `NSAudioCaptureUsageDescription` and `NSMicrophoneUsageDescription` in `src-tauri/Info.plist`. Do not request CoreGraphics screen-capture permission for this audio-only recording path.
- Preserve the startup recording-access notice and focus rechecks. Permission checks must not start capture or save audio. Keep unknown/unavailable states distinct from granted; do not cache grants across app builds or report readiness when the OS check cannot establish access. System audio's dynamically loaded TCC preflight/request functions must degrade to an explicit unverified state if unavailable.
- Before installing, run `node --test scripts/prepare-local-build.test.mjs`, the frontend build, and Rust checks appropriate to the change. On macOS verify the final bundle with `codesign --verify --deep --strict --verbose=2` and inspect its `CFBundleShortVersionString`, `CFBundleVersion`, and audio permission descriptions.
- After installation, distinguish the on-disk version from the app process still running. Tell the user to quit and reopen Lore; do not interrupt an active recording or discard unsaved work to force a restart.
